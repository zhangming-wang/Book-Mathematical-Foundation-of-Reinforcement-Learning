# PySide6 网格世界编辑器

这是独立的中文桌面编辑器，提供棋盘编辑、逐格奖励与策略配置、JSON 保存/加载，以及计算结果的显示接口。

“贝尔曼方程”按当前策略计算有限步状态价值；“贝尔曼最优方程”计算最优价值和动作，自动切换到最优策略，并用绿色线显示该策略中的最高分目标路径。接口位于 [bellman.py](bellman.py)。

## 安装与启动

需要 Python >= 3.10 和 PySide6（`requirements.txt` 要求 `PySide6>=6.5,<7`）。在仓库根目录执行：

```bash
python3 -m pip install -r "src/requirements.txt"
python3 -B "src/main.py"
```

启动 GUI 需要桌面显示环境。入口是 [main.py](main.py)，不依赖原 Python 演示的 `numpy`、`matplotlib` 或参数解析器。程序运行时可在启动终端按 `Ctrl+C` 退出。

## 棋盘与编辑

默认棋盘为 5 行 × 5 列，每格宽、高均为 10 mm，折扣系数 γ 为 0.9，初始缩放为 300%。开始格位于第 1 行第 1 列，目标格位于第 5 行第 5 列；所有格的五个动作概率初始均为 0.2。

| 类型 | 棋盘标记 | 默认奖励 |
| --- | --- | --- |
| 普通 | 白色 | 0 |
| 开始 | 白色背景，左上角五角星 | 0 |
| 目标 | 蓝色 | 1 |
| 禁止 | 黄色，允许进入 | -1 |

每格的奖励均可单独修改；类型的默认奖励不是固定约束。棋盘显示 `r`、非零动作的箭头及概率，上下动作概率紧邻对应箭头，原地概率居中显示在环形箭头内。收到有效计算结果后才显示状态价值 `V`。

行列标题从 1 开始，固定在棋盘上方和左侧，滚动时保持可见。单击选择方块，在右侧修改类型、得分和五项概率，再点击“应用当前方块”。每项概率必须在 `[0, 1]` 内，并满足 `abs(sum(probabilities) - 1) <= 1e-6`；编辑器不会自动归一化。

宽高、γ、缩放和概率的数值调节框统一保留小数点后三位。加载配置时，未编辑字段保留文件中的原始精度；概率合计与校验使用实际待应用的数值。

- 切换到其他方块时，尚未应用的当前格编辑会提示选择“应用”“放弃修改”或“取消”。
- “恢复默认输入”填入当前类型的默认奖励及五个 0.2，仍需点击“应用当前方块”。
- “将这组概率应用到全部方块”经确认后只复制五项概率，保留各格的类型和奖励。
- 棋盘必须恰有一个开始格和一个目标格。现有角色不能直接删除或改为其他类型；请先在普通格或禁止格设置新的对应角色并应用。原角色格自动恢复为普通格、奖励 0，保留原概率。

全局参数需要点击“应用棋盘设置”后生效。改变行数或列数会先请求确认，再重建棋盘并重置所有格的类型、奖励、概率及未应用编辑；只改变宽、高或 γ 会保留各格配置。行列范围为 1–100，至少需要两个格，不能使用 1 × 1 棋盘；宽、高范围为 0.01–1000 mm，γ 范围为 `[0, 1]`。

在“棋盘设置”中输入“禁止格数量”，点击“随机生成禁止格”可重新生成共 n 个禁止方块。数量范围为 `0～行数×列数−2`，位置随机且不重复，避开开始和目标格。已有禁止格先恢复普通格、奖励 0，再把选中位置设为黄色禁止格、奖励 -1；各格的动作概率保留。n=0 会清除全部禁止格，生成后仍可逐格修改奖励。

随机生成前须应用全局棋盘参数；当前格有未应用编辑时会提示“应用／放弃修改／取消”。生成后刷新选中格、清除旧计算结果并标记配置已修改。生成的位置通过原有 JSON 的格子数据保存，加载后恢复同样的布局。

棋盘初始在视图区居中。左键单击选择方块，左键按住拖动平移棋盘，即使棋盘小于视图区也能拖动。直接滚动鼠标滚轮，以当前鼠标位置为中心缩放，向上放大、向下缩小，无需按住中键。也可以使用缩放输入框、放大/缩小按钮或“适应窗口”调整视图；“适应窗口”会重新居中棋盘。保存、加载、应用和计算均通过按钮操作，没有应用快捷键。应用方块、批量概率或棋盘设置会清除之前显示的计算结果。

“计算与结果”区域的“计算轮数”默认 100，范围 1–1000。每轮更新整张棋盘一次，第 n 轮显示未来 n 步的状态价值 `V`，右侧显示选中格的数值。目标格继续行动和得分，不自动终止。

“路径最大步数”独立控制每轮最优策略的目标路径搜索长度，默认 `行数×列数−1`，可在 `1～行数×列数−1` 之间调整。这是路径不重复经过方块时的最大可能动作数。即使只计算一轮，也会按该轮策略搜索完整目标路线，不要求一步到达目标。没有目标路径时仍显示价值和最优动作；缩短路径上限也可能使路径不可展示。修改计算轮数或路径上限会清除旧结果，不写入棋盘配置，也不标记棋盘已修改。

“路径选择”下拉框可查看该轮策略允许的全部目标路线：

- 默认选中“最优路径”，同时绘制到达前回报并列最高的全部路线。
- 后续每项对应一条完整路线，按“完整得分 - 步数”显示，例如 `-1.0134142280088763 - 20 步`，按原始得分从大到小排序；同分的不同路线仍分别保留。
- 选择得分项后，只绘制该条绿色路线；下方一行显示最高得分路径和可选目标路径的数量。悬停在选项上可查看路径编号及完整坐标，坐标为从 1 开始的“行、列”。
- 逐轮刷新时，按坐标序列保留仍存在的选中路线；若该路线已不在新策略中，则回到默认“最优路径”。没有目标路线时禁用下拉框。

计算方式可以选择：

- **一次算完**（默认）：在后台计算所有轮次，只显示最终结果；最优路径也只在最后一轮生成。
- **逐轮播放**：每更新完整张棋盘一次，就显示该轮结果，再等待“播放间隔”后计算下一轮。第 n 轮对应未来 n 步的价值；最优计算每轮同时更新动作箭头、绿色路径和路径回报，每轮使用相同的独立路径长度上限。

播放间隔默认为 **0.500 秒**，范围 0–60 秒，保留三位小数，播放中可以调整。间隔表示结果显示后等待多久；每轮实际用时还包括计算和路径搜索时间。“暂停／继续”保留计算进度，“停止”中断当前计算并保留最后显示的一轮；再次点击公式按钮会从第 1 轮重新开始。

“重置棋盘”与“暂停／继续”“停止”并排，点击会清除状态价值、最优策略、绿色路径、路径选项和计算进度，恢复配置中的动作箭头与概率。格子类型、奖励、禁止格布局、当前选择、视图位置和计算／播放参数保留，配置的保存状态也不改变。计算中或暂停时点击，会先取消后台任务，待线程结束后重置；之后可以重新点击任一公式按钮开始计算。

计算和路径搜索运行在工作线程，等待间隔使用 Qt 定时器，期间仍可选格查看价值、拖动、缩放和切换策略显示。计算中暂时锁定棋盘编辑、随机生成、加载、计算轮数、路径上限和计算方式；完成或停止后恢复。关闭窗口及终端 `Ctrl+C` 都会先取消并回收工作线程。播放方式与间隔不写入棋盘 JSON。

## 保存与加载

“保存配置”和“加载配置”使用 UTF-8 JSON，当前格式为 `format_version: 1`，保存以下内容：

- 行列数、方块宽高、γ 和缩放倍数 `zoom`（例如 `3.0` 表示 300%）。
- 按行排列的 `cells[row][column]`；每格包含 `kind`、`reward`、`probabilities`。
- `kind` 为 `normal`、`start`、`target` 或 `forbidden`；JSON 中的 `probabilities` 是以 `up`、`down`、`left`、`right`、`stay` 为键的对象。

JSON 不保存计算轮数、路径最大步数、播放方式、间隔、状态价值、求解后的最优策略或路径结果。加载配置后需要重新计算。

保存时，当前格尚未应用的有效编辑会自动应用后写入文件；无效输入会阻止保存。**全局棋盘参数不会在保存时自动应用，必须先点击“应用棋盘设置”。** 缩放立即生效并参与保存。

保存先校验配置，再写临时文件并替换目标文件。加载先完整校验版本、字段、尺寸、数值、概率及唯一开始/目标格，校验成功后才替换当前棋盘；无效文件会保留当前棋盘。加载其他配置或关闭窗口时，已修改的配置、缩放及未应用输入都会触发“保存”“放弃”或“取消”提示。

## 模型与动作约定

[model.py](model.py) 使用以下约定，接入公式时请按此处理：

| 项目 | PySide6 编辑器 | 原 `python_version` 演示 |
| --- | --- | --- |
| 内部坐标 | 零基 `(row, column)`，即 `(行, 列)` | 零基 `(x, y)`，即 `(列, 行)` |
| 动作顺序 | 上、下、左、右、原地 | 下、右、上、左、原地 |
| 禁止格 | 允许进入，取该格奖励 | 留在原地，取 `reward_forbidden` |
| 碰壁 | 坐标截断至边界，取当前格奖励 | 留在原地，取 `reward_forbidden` |

`ACTIONS = ("up", "down", "left", "right", "stay")` 是内存中所有五项概率列表的顺序。对应行列位移依次为 `(-1, 0)`、`(1, 0)`、`(0, -1)`、`(0, 1)`、`(0, 0)`。界面的行列编号是在内部坐标上加 1。

```python
config.transition(row, column, action)
# 返回 ((next_row, next_column), destination_reward)
```

`GridConfig.transition()` 是不修改配置的纯辅助函数，每次调用耗时为 O(1)。它校验当前坐标和动作，将下一坐标限制在棋盘内，并返回目的格的奖励；禁止格、原地动作和碰壁都遵循这一规则。它不返回 `done`，也不将目标格自动设为终止或吸收状态。

公式实现应在循环前调用一次 `config.validate()`，随后重复调用 `transition()`，避免每一步扫描整个棋盘。`config.cells[row][column]` 提供该格的类型、奖励和策略；`config.start`、`config.target` 返回零基角色坐标。

## 接入计算接口

[bellman.py](bellman.py) 的两个入口签名为：

```python
def evaluate_policy(config: GridConfig, max_count: int = 100) -> CalculationResult:
    ...

def solve_optimal_policy(
    config: GridConfig,
    max_count: int = 100,
    *,
    path_max_count: int | None = None,
) -> CalculationResult:
    ...
```

`evaluate_policy()` 使用 `V_0 = 0`，按 `V_(n+1)(s) = sum(pi(a|s) * (reward + gamma * V_n(next_state)))` 更新恰好 `max_count` 轮；它与有限深度递归计算相同，逐层更新避免递归深度限制。所有概率大于 0 的动作均参与计算，下一状态和奖励来自 `transition()`；目标格继续参与计算，有限步情况下也支持 γ=1。返回的是有限步价值，没有作无限步收敛判断。

`solve_optimal_policy()` 按 `V_(n+1)(s) = max(reward + gamma * V_n(next_state))` 更新相同步数。输入概率大于 0 的动作可参与比较，概率大小不参与评分，概率为 0 的动作不可用。最后一轮中并列最优的动作按等概率显示，比较容差为绝对误差 `1e-9`。

当前路径搜索沿用该轮策略，保存最多 `path_max_count` 步、不重复经过格子且首次到达目标就结束的全部路线到 `all_paths`，按 `sum(gamma ** step * reward)` 得到各条路线的到达前回报并降序排列；其中并列最高分路线同时保存在 `best_paths`，用于默认显示。`path_max_count=None` 默认使用格子总数减一，独立于价值迭代轮数。首轮显示完整路线不代表长期策略已经收敛。路径回报不含到达目标后的收益，可能与起点 `V` 不同；路径展示不按剩余步数切换各轮策略。没有到达路径时两个列表都为空；大量并列动作下枚举并保留全部路径的时间和内存开销会增加。

界面应用有效的当前格编辑后，将当前 `GridConfig` 的深拷贝和输入框中的 `max_count` 传入对应函数；最优计算还会传入独立的 `path_max_count`。全局参数仍须先应用。

`iterate_calculation(config, max_count, optimal=False, path_max_count=None)` 按顺序产生 `(轮数, CalculationResult)`，每轮使用独立价值和策略数组。最优逐轮结果的路径沿用该轮策略和整个运行期间固定的路径上限，保留现有简单路径与回报规则。批量接口使用同一递推过程，跳过中间结果和中间路径搜索，因此最终结果与逐轮播放一致。

算法的 `checkpoint` 可选关键字参数用于暂停和取消；价值更新按行、路径搜索按分支检查。`calculation_worker.py` 负责后台计算及帧交接，`window.py` 用单次 Qt 定时器调度下一轮。只有界面显示并确认当前帧后才安排后续计算，避免积压帧或暂停后继续刷新。路径搜索采用深度优先展开，保留全部策略允许的目标路径，不因得分较低而丢弃，也不限制并列路径数量。

返回类型定义在 `model.py`，字段形状如下：

| 类型与字段 | Python 类型 | 形状与约定 |
| --- | --- | --- |
| `CalculationResult.values` | `list[list[float]]` | 必填，`rows × columns`，`values[row][column]` 为有限状态价值 |
| `CalculationResult.optimal_policy` | `list[list[list[float]]] \| None` | 默认 `None`；提供时为 `rows × columns × 5`，每格按 `ACTIONS` 排列，概率校验与输入策略相同 |
| `CalculationResult.best_paths` | `list[PathResult]` | 默认空列表；由算法返回所有并列最高分路径 |
| `CalculationResult.all_paths` | `list[PathResult]` | 默认空列表；最优计算返回该轮策略允许的全部目标路线，按原始回报降序排列 |
| `PathResult.coordinates` | `list[tuple[int, int]]` | 必填，非空零基 `(row, column)` 序列，含开始格和目标格 |
| `PathResult.score` | `float` | 必填，有限路径得分，由算法计算 |

界面通过 `CalculationResult.validate(config)` 校验结果后显示。路径必须从 `config.start` 出发、在 `config.target` 结束；所有坐标都须在棋盘内，相邻坐标只能上下左右移动一格或原地停留。校验不判断公式是否正确，也不判断路径是否确实最高分。

`evaluate_policy()` 必须返回状态价值，可同时返回最优策略和路径；`solve_optimal_policy()` 的界面入口还要求 `optimal_policy` 不能为 `None`。有效结果会启用相应显示：每格显示 `V`，有最优策略时可切换“当前策略/最优策略”，有路径时可勾选“显示绿色路径”。默认绿色线条覆盖 `best_paths` 返回的全部路径，共用线段只画一次；下拉框可选择 `all_paths` 中的单条路线，选择路径不改变价值或动作箭头。手写结果仅提供 `best_paths` 时，下拉框仍可逐条查看这些路径。

当前普通策略评估只返回状态价值，最优计算返回价值、最后一轮动作概率和目标路径。输入概率合计容差为 `1e-6`，动作与路径得分的并列容差为 `1e-9`。编辑器负责校验和显示返回结果，路径枚举与评分由公式模块完成。

## 测试

在仓库根目录的 `src/` 目录执行：

```bash
cd src
QT_QPA_PLATFORM=offscreen python3 -B -m unittest discover -s tests
```

本工作环境运行测试时同时设置 `TMPDIR=/tmp/opencode`。`offscreen` 用于无桌面显示的测试，正常打开编辑器仍使用前面的启动命令。
